# 02 — Hardware UX review: SkurkyMello on the M-VAVE FM-1

Reviewer role: hardware UX / "is it an instrument?"
Scope: `mello/mello_ui.c` (2565 lines), `mello_ui.h`, `overlay/dinghy.c`, the engine/transport/storage APIs the UI calls, the docs in `docs/`, and `original.html` as the reference.
All line numbers refer to `mello/mello_ui.c` unless another file is named.

**Verdict in one line:** the port moved the HTML's *parameters* onto the FM-1, but not its *direct manipulation*. Every musical gesture goes through "pick a page, then pick a step, then turn a knob that edits only that step". The panel's strongest assets do almost nothing: 27 keys that never make a sound, 3 of 7 encoders that are dead or duplicated, LEDs that never show the playhead, and REC and EDIT that do nothing on most pages.

### 1.5 Navigation tree and press counts

```
HOME ─┬─ SEQ ──► STEP(4 layers) ─SEQ─► SEGMENT(2) ─SEQ─► LOOP(3) ─SEQ─► SLOT SEQ ─SEQ─► (STEP)
      ├─ SEL ──► KEY/SCALE
      ├─ ENV ──► SOUND(5 layers, last layer remembered) ─ENV─► SAMPLE(4) ─ENV─► SOUND
      ├─ LFO ──► SOUND/LFO ─LFO─► DOT(4 targets) ─LFO─► TURING(3) ─LFO─► SOUND/LFO
      ├─ ARP ──► SUB(5) ─ARP─► CHORD(5)
      ├─ FX  ──► AUDIO FX(5)
      ├─ GLO ──► GLOBAL(2)
      ├─ SAVE ─► SLOTS(2)  (SAVE again = write slot)
      └─ B5/F#4 (most pages) ─► RANDOM   (B1/G#3 = reroll)
```

There is one page level, but each page has up to five layers reached with SELECT. The effective depth is **page → layer → selected item → knob**, so up to four levels.

|---|---|---|

## 2. The first 30 seconds

### FM-1

| t | Action | What happens |
|---|---|---|
| 0 s | Power on | No splash (still WP-I, `UI_VISUAL_LANGUAGE.md` "Splash"). The last saved project loads (dinghy.c:172). On a fresh unit you get the defaults (`mello_engine.c:412-445`): 16 steps, pitch = i%7 (a staircase), 80 BPM, C minor, saw, follower sub on. **Transport stopped, silence.** |
| 0 s | Screen | Header `SKURKYMELLO  HOME A  S80`. Segment bracket "A". A 16-column staircase skyline. `S1 MIDI 60` and `P1 R1 SGL Q100`. Hint row `B5:RANDOM`. Footer `PITCH 0 · PULSE 1 · RATCH 1 · GATE SINGLE`. Status `S1 P1 G1`. Only W1's LED is lit (the selected step). |
| 2 s | Press a key (most people do this first) | **No sound.** A white key moves the selection outline. A black key does nothing, unless it is F#4, which jumps to RANDOM. The user cannot tell what happened. |
| 4 s | PLAY | An ascending C-minor saw scale on 16ths at 80 BPM with 24% reverb and 12% delay. Nice tone, but it is an exercise, not a loop. Key LEDs do not follow the beat. |
| 8 s | Look for "random" | The hint says `B5:RANDOM`. Nothing on the panel is labelled B5, so the user has to count the black keys (F#4, the 6th). |
| 12 s | F#4 | RANDOM page. The help box reads **"REC REROLL   EDIT+REC CLEAR"** (2106), but REC is inert (1292). Pressing REC does nothing, so the user decides the feature is broken. |
| 20 s | (If they read the hint row) G#3 (B1) | Reroll at MED with all 13 targets. Now it is a loop. |
| 25 s | Want it darker (turn "the filter") | No filter on screen. K1-K4 on HOME edit step 1's pitch, pulses, ratchet and gate. Turning K1 changes one note. The filter is ENV → K3, and only if SOUND was last left on the OSC layer. |
| 30 s | — | A passable loop, after about 3 deliberate actions, 2 of which needed decoding. No knob has done anything "big" yet. |

Best case for a user who knows the device: **PLAY, F#4, G#3 = 3 actions to a randomized loop.** Shaping its sound takes 2-4 more actions per parameter.

### HTML (`original.html`)

Defaults are identical: `makeStep` i%7 (163-169), 80 BPM (416), C minor (485-486), saw (495), stopped (413). The difference is what is in reach:

- The title bar shows key, scale, steps and bars, plus PLAY/STOP and BPM/TAP (3090-3140).
- **⚡ RANDOM** is one click, right beside SAVE/LOAD/CLEAR, and the target chips are all visible (3330-3354).
- Every step's pitch lane is clickable by height, with per-step +/- pulses and ACC/SLD/SUB toggles in place (3560-3667). There is no "select first".
- FILTER CUTOFF/RES, ENVELOPE, DELAY, REVERB, DISTORTION and MASTER are all on the same page (4191-4326).
- Space = play and arrows = edit pitch (2157-2175).

**Same sound and same number of clicks to the first random loop. But in the HTML the next 20 decisions are each one visible gesture away. On the FM-1 each one is a remembered page plus layer plus selection.** That gap is the "feel" the owner is missing.

## 4. What the FM-1 could do better than the HTML, and the port does not use

| Hardware asset | Could be | Port today |
|---|---|---|
| 16 white keys + 16 LEDs | **Step buttons with a running-light playhead**, Volca/TR style. LED on = active step, a moving inverted LED = playhead. Tap = mute/unmute. Hold + turn = edit that step. Hold two keys = edit a range. | Selection only. One LED (2497) |
| 27 keys as a keyboard | **Live transpose** (latch the sequence root to the key pressed, quantized to the next step or bar), **audition while stopped**, **step-record** with REC. The HTML cannot do any of this. | Never sounds |

## 5. Proposed control layout: "PERFORM HOME" + at most 2 levels

### 5.1 Principles

1. **HOME is the instrument.** You can make a track from HOME alone: steps, notes, randomize, the four sound macros and tempo.
2. **Two levels maximum:** Level 0 = HOME. Level 1 = a domain page opened by one button. Layers *within* a domain are reached by pressing the same button again (the SEQ pattern at 260) or with SELECT. There are no cross-page chains (remove the LFO→DOT→TURING and ENV→SAMPLE toggles).
3. **Page buttons always open layer 0** of their domain, so the display never depends on history. Remember the last layer only while you stay on that page.
4. **Every control on screen does what its silkscreen or on-screen label says.** Black-key actions are drawn as a key-shaped strip whose positions match the black keys, not as "B5:".
5. **Gestures are non-destructive by default.** Destructive actions are held for 1 s, and reroll has undo.

### 5.2 HOME (PERFORM) — level 0

**Screen** (reusing the existing skyline, 1715-1788): skyline full width. The header drops the wordmark (it moves to the splash) and shows `C MIN · 120 · 2BAR · SLOT 03`. The footer shows the four **macro** values as arcs. When a step key is held, the footer swaps to that step's PITCH(note name) · PULSE · RATCH · GATE, and the held step is highlighted.

| Control | HOME behaviour |
|---|---|
| **W1-W16** | **Step keys.** Tap = toggle the step on/off (skip). Hold = focus the step, so K1-K4 edit it while held and the footer swaps. Hold + another W = focus a range. While stopped, a tap also **auditions** the step. LED = step active. The playhead is shown by inverting the LED. |
| **OCT− / OCT+** | Steps 1-16 / 17-32 (as now). The LED on the button shows which bank, and the banner shows it too. |
| **K1** | Macro **CUTOFF** (`sound.filter_cut`) |
| **K2** | Macro **DECAY**: amp decay+release scaled together (`decay_ms`, `release_ms`) |
| **K3** | Macro **SPACE**: delay wet + reverb wet on one curve (`delay_wet`, `reverb_wet`) |
| **K4** | Macro **DRIVE** (`fx.dist_amount`, already gain-compensated by E2) |
| K1-K4 while holding a step | PITCH (note name) · PULSES · RATCHET · GATE for that step (current `adjust_home`) |
| **SELECT** | **TEMPO** (BPM, with acceleration) |
| **ALGORITHM** | **INTENSITY** LOW/MED/HIGH, shown in the header |
| **PRESETS** | **PATTERN**: browse slots. It **queues on the next bar** and shows `→03` in the header. Click/second action is not needed because the queue is the commit. Turn back to cancel. |

### 5.3 Level 1 domain pages (one button each, layers by re-press or SELECT)

Depth: **HOME → page → layer.** No feature is more than **2 actions** from HOME plus the knob turn. The ten most-used musical moves (play, random, undo, cutoff, decay, space, drive, tempo, transpose, step on/off) are **1 action** on HOME.

### 5.4 Rotary hygiene (applies everywhere)

- **No booleans on encoders.** Move them to black-key toggles with a visible state, or to a threshold such as "turn past 50%" for mix-like parameters.
- **Acceleration:** step size grows with detent rate. Every handler must honour delta size instead of `delta>0?10:-10`.
- **Music units:** note names (C4), Hz/BPM, bars, percent.
- Keep the WP-C single-source label/handler table (`context_actions` 407 is the right pattern), and extend it to K1-K4.

### 5.5 Implementation pointers (smallest high-impact slice first)

1. **Fix the lies:** strings at 2106, 2115 and 2239. Guard 1259 so SEL on STEP does not navigate (or drop the SEL+note gesture).
2. **Mark storage dirty in `mark_edit`** for persistent fields (131), and show "SAVED" in `draw_status`.
3. **Playhead and step LEDs:** add `display_step` and the `!skip` map to `calc_key_leds` (2493).
4. **HOME macros:** in `adjust_home` (567), make K1-K4 drive cutoff/decay/space/drive unless a step key is held. This needs a held-key mask from the platform. `fm1_in` already exposes `buttons` (dinghy.c:245); a matching `notes` level mask is needed instead of press edges only (dinghy.c:241).
5. **One-press RANDOM on HOME:** set `context_actions[MELLO_UI_HOME][0] = REROLL` (408) and fire `mello_engine_randomize_steps_intensity` directly.
6. **SELECT/ALG/PRESETS** on HOME → tempo / intensity / queued pattern (989-1025).
7. **Audition and transpose:** inject NOTE events through the existing event sink (`mello_transport_set_event_sink`, dinghy.c:214). The latched transpose maps onto `project.root_note`, quantized in `mello_transport_poll`.
8. Collapse the LFO/ENV/ARP carousels into layered domain pages (1261-1287) and reset to layer 0 on entry.

The control-grammar work (WP-C) was the right instinct: one meaning per control. But it optimised *consistency across 16 pages* instead of *immediacy on one*. The proposal keeps that grammar (PLAY = transport, REC = record, EDIT = focus, white = position, black = verbs) and makes HOME a complete instrument, so the other pages become optional depth.
